## 1. 三项指标的排版（M6-03#1）

| 步骤 | 预期 |
| --- | --- |
| 开始录制，观察主窗口状态栏 | 出现「采集 x.x / 编码 x.x fps · 丢帧 n」，与计时、剩余可录同一行且不换行截断 |
| 观察悬浮工具条 | 第三行显示同一组指标；拖动悬浮条后数值继续刷新 |
| 暂停 3 秒再恢复 | 采集/编码 fps 重新起算（不把暂停空洞算进滑窗）；丢帧数不清零 |
| 静止桌面 vs 播放视频 | 静止时采集 fps 接近 0（DXGI 变化驱动），编码 fps 仍在 30 附近；播放视频时采集 fps 抬升 |

截图：`round30-metrics.png`（录制中，状态栏 + 悬浮条）。

> 自动化已断言：recorder 侧 1Hz 采样、丢帧注入可见、UI 数值来自快照（`snapshot ... capture_fps=`）。
> 本条只确认排版与可读性。

## 2. 诊断包导出（M8-14#1）

| 步骤 | 预期 |
| --- | --- |
| 右键托盘 → 「导出诊断包…」 | 弹出文件夹选择对话框（默认输出目录） |
| 选择目录并确认 | 弹出结果框，显示导出路径、文件数、字节数、耗时 |
| 打开导出目录 | 只有 `version.txt` / `gpu.txt` / `log.txt` / `config.ini` 四个文本文件 |
| 用文本编辑器打开 `log.txt` | 含最近 10 分钟的 app 日志与本次 recorder 日志尾部；路径显示为 `C:\Users\<user>\…` |
| 故意在录制中导出 | 导出不打断录制（≤2s），录制计时继续 |

截图：`round30-diag-menu.png`（托盘菜单里的「导出诊断包…」入口）。

> 自动化已断言：四类产物、无 png/jpg/mkv/音频签名、<5MB、≤2s、用户名脱敏、UI/CLI 两个入口。
> 待人工补：**文件夹选择对话框**与结果框的截图（自动化无法点击系统模态对话框）。

## 3. 日志分级（M8-14#2）

| 步骤 | 预期 |
| --- | --- |
| INI 写入 `[log] level=debug` 后启动 | 日志出现 `[debug] …` 行；状态栏行为不变 |
| 启动参数 `--log-level warn` | 日志只剩异常行（如自检失败 `[warn] preflight_failed …`） |
| 两者同时给 | `--log-level` 覆盖 INI |

> 分级**重启生效**（不做运行中热切换）：`--log-level` 在启动时定档，INI 改动需重启应用；
> 这一口径写进了 `--help` 与 CONTRACT。运行中切换不在本轮范围。

> 自动化已断言：debug > info > warn 行数梯度、INI 生效、CLI 覆盖；本条只确认「改 INI 后重启」这一人工操作路径。

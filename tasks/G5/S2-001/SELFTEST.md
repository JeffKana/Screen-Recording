# SELFTEST: S2-001 控制闭环

本文件记录本轮自测中踩到的「假通过/假失败」陷阱，供后续轮次复用。

## 1. C2「暂停期间不写盘」的假通过（D-27）

第一版用例：后台启动录制，在暂停窗口内两次轮询 `.part` 大小。

问题：用例复用 `pause.mkv`，该文件已被上一条用例占用，触发同名避让，
实际写入 `pause_001.mkv.part`，两次采样都读到「文件不存在」→ `0 - 0 = 0` → **PASS**。

修法：
1. 先断言 `part_bytes_at_pause > 0`，再比较增长；
2. 数据来源改为录制器自报（`part_bytes_at_pause` / `part_bytes_at_resume`），
   不再依赖外部轮询时序。

**通用教训**：任何「A - B == 0」形态的断言，必须先证明 A、B 来自有效样本。

## 2. Copy-Item 恢复源码导致跑旧二进制（轮 19 遗留）

`Copy-Item` 保留旧时间戳，MSBuild 判定 `.obj` 更新从而跳过重编，用例跑在旧二进制上，
出现 14 PASS / 1 FAIL 的假失败。

修法：恢复源码后必须确认构建日志里出现该文件的编译行，否则本轮验收结论无效。

## 3. 暂停恢复期的两个真实缺陷

- D-25：转换器绑在已释放的 D3D11 设备上 → `VideoProcessorBlt` 失败 → CPU 路径跨设备拷贝崩溃。
- D-26：重建转换器时清空缓存帧 → 恢复后既无新帧又无可补帧 → 丢 4 帧、空洞 167ms。

两者的共同教训：**「释放—重建」之间必须重新确认资源归属**；
指针相等不能作为「资源未变」的证据（旧对象释放后地址可被复用）。

## 4. 音轨差的观测口径

`audio_last_pts_ms` 由累计采样数推算，不含编码器末尾缓冲；
实测暂停场景差 234ms、非暂停 53ms，均 ≤ 300ms 判据，但**暂停会显著放大尾部差**，
已记入已知偏差。

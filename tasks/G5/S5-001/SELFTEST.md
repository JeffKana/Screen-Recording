# SELFTEST: S5-001

## 1. 「连上又立刻断开」被误报成「从未连接」

首版 D/E 场景失败：客户端连上后 0ms 就 dispose，服务端非阻塞 accept 捕不到握手，
`ConnectNamedPipe` 返回 `ERROR_NO_DATA`，被我当成「上一客户端残留、重建实例」，
最终超时 → `control=absent`。

两处修：

1. 产品侧：`PipeServer::ClientSeen()` 记住「曾有客户端」，超时后报 `lost` 而非 `absent`；
2. 用例侧：改在连接后 400~600ms 再断开——真实 UI 也不会连上即断。

**教训**：`absent` 与 `lost` 是两种不同的用户可见状态（前者「没接 UI」，后者「UI 崩了」），
不能合并。

## 2. 半帧用例本身写错了

首版发「半个帧头」+「另一个完整帧」，两者拼起来是垃圾头 → 服务端按协议断开，
`rejected` 恒为 0，用例判失败。

正确写法：把**同一个帧**拆成 6 + 剩余两段发。这样才真正检验「半帧不消费、补齐后解析」。

**教训**：负向用例要先确认自己构造的输入是「目标场景」，不是「另一种错误」。

## 3. 修改主循环作用域

`manual_pause` 原先声明在 `if (!paused && ...)` 块内，恢复段要用时已出作用域。
改为在循环外声明、块内赋值。编译期即暴露，无运行期风险。

# EVIDENCE: S3-001 故障注入矩阵（T-16a）

锚点（轮 22 裁定，纠正 08 §11.2 的 ER 编号错误）：
**ER-04 磁盘耗尽、ER-06 路径不可写、ER-02 强杀（代理 ER-01 断电）、M8-08 编码器失败**。
ER-08（TDR）属 V1.5（M8-09），**未覆盖**，不得以「跑一次没崩」冒充。

复现：`pwsh -NoProfile -File verify/cases/g5_inject.ps1 -BuildDir build-msvc -Config Release`
结果：**28 PASS / 0 FAIL**（每项注入各 3 次，逐一比对稳定性）。

## ER-04 磁盘耗尽 ×3

| 轮次 | disk_stop | exit | 成品 | .part | 可解码 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 0 | 1.86 MB | 无 | 是 |
| 2 | 1 | 0 | 2.35 MB | 无 | 是 |
| 3 | 1 | 0 | 2.28 MB | 无 | 是 |

判定元组完全一致。文件大小不同属正常（停止时刻抖动），不计入「不稳定」。

**用例教训**：首版把 stop 线在循环外算一次，第 2、3 轮因上一轮占用了空间而直接撞上
「开录前拒绝（exit 12）」，测到的是另一条分支。改为每轮重算。

## ER-06 路径不可写 ×3

开录前：`exit=13`、无成品、无 `.part`，三次一致。

**录制中撤权：判 BLOCKED。** Windows 的 DACL 对「已打开句柄」不生效，撤权后写入仍然成功，
无法在不引入 `--fail-write-after` 的前提下构造真实写失败。按裁定留待轮 23。

## ER-02 强杀 ×3（代理 ER-01）

| 场景 | 强杀时刻 | 修复后时长 | 丢失 | 可播 | 含音轨 |
| --- | ---: | ---: | ---: | --- | --- |
| 录制中 | 8.0s | 4.97s | **3.03s** | 是 | 是 |
| 暂停中 | 9.0s | 4.97s | **4.03s** | 是 | 是 |
| 收尾前 | 4.7s | 1.90s | **2.80s** | 是 | 是 |

三次结果在秒级完全一致，满足 M8-01「恢复到崩溃前 ≤10s 的内容」。

### 本轮据此修掉的真实缺陷（D-30）

首轮「暂停中」只捞回 **3.44s**：进入暂停时没有把内存中的 Cluster 落盘，
暂停期间被杀即丢失整个未落盘簇区间。

修法：`MkvWriter::FlushPending()`，暂停入口立即落盘。修复后 3.44s → 4.97s（+1.5s，正好一个簇）。

剩余 ~1s 差距来自**编码器内部缓冲**（B 帧重排尚未出包），属设计内损失；
未在暂停点强制 DRAIN——那会强制插入 IDR 且可能破坏编码器状态，代价大于收益。

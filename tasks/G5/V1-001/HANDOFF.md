# HANDOFF: G5/V1-001（覆盖模型 + 台账）

## 我改了什么接口？

- `coverage_model.card_delivery()` 语义不变，但**缺失项默认值**从「已实现」改为「有卡未实现」
  （改动点在 `build_rows` 的 `delivery.get(owner, {}).get(rid, ...)` 默认参数）。
- `coverage_report.py` 的表头说明与 `--self-test` 断言同步翻转。
- 无 CLI 参数变化：`--write` / `--check` / `--self-test` 用法不变。

## 下游需要接什么？

- **今后每张任务卡必须写 `## 交付状态`**，否则其子句一律「有卡未实现」并进 C8 挂账。
  卡模板（`references/delivery-contract.md` §1.1）已把该节列为必填。
- **子句级交付**（`- M3-04#1: 已实现`）尚未支持；若下一轮要做，需同时改
  `DELIVERY_LINE` 正则与 `build_rows` 的 implemented 判定，并补自检。

## 已知限制是什么？

1. 覆盖表仍是「需求级交付、子句级统计」：一条需求有任一子句未交付，其余子句也显示
   「有卡未实现」（偏保守，不会假绿）。
2. 模型只读卡，不读 EVIDENCE；「已实现 + 无证据」不会被抓出来，靠验收侧核对。

## 哪些需求我**没**做完？

- 无需求交付（工具卡）。子句级交付声明未实现，已在 SELFTEST §5 记为下一轮口径变更候选。

## 2. 两处红项：都成立，处置如下

### R1 · `g5_closeout` 17/1：断言把"不可用条数"写死

```
FAIL m6-04-02-hw-unavailable-with-reason — 三厂商硬编 id 命中=3，逐条标注 available=0 + 非空 reason 的规范行=4
```

产品把 `mf-h264-hw` 诚实标为 unavailable（第 4 行），用例却断言"恰好 3 行"。**这是断言写死了数量，不是产品错。**

裁定：改成**数量无关**的两条断言——
1. 三个厂商 id（nvenc/qsv/amf）**都在** unavailable 列表里；
2. **每一行** unavailable 都有非空 reason。

再补一条反向：人为抹掉某行 reason → 必须 FAIL。归属轮 48（`verify/cases/g5_closeout.ps1` 属 V1-004 卡，本轮未越界，判断正确）。

### R2 · `g5_format` 首跑 14/1（单秒 12,799kbps）

单秒挡板 2× = 12,000，实超 799kbps。清场复跑 15/0。这是**M3-04#1 的贴线风险**，不是回归。

裁定：轮 48 连跑 5 次 `g5_format`（含活动场景）；任一次单秒超 2× → **M3-04#1 回退 PARTIAL**，不许只报最好那次。

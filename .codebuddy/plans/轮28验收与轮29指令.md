## 3. 三个发现

**F1 · 协议"兼容"只做了解码，没做行为（一般级）**

`Decode(StateSnapshotPayload)` 对旧 10 字节载荷默认 `kind=0`（`Protocol.cpp`），契约 §7 也写了「旧载荷按 kind=0 解析，版本保持 1」。
但 `srctl` 只把 `kind=1` 当命令结果（`srctl/main.cpp:182`）。于是**新 srctl + 旧 recorder** 会跳过全部快照，循环 8 次后静默返回 0——没有结果、没有报错。

同 build 发布时不会触发，但契约文字暗示了"旧载荷可用"，行为上并不成立。二选一：
- 把协议版本提到 2，客户端对不上就明确拒绝（干净）；
- 或 srctl 在"连续 N 条 kind=0 且始终无 kind=1"时退化为旧行为（首条快照即结果）。

我倾向后者的一半 + 一句日志，成本最低。**别让"兼容"停留在注释里。**

**F2 · 抖动阈值：允许调整，但要落到 05，并补一条产品级断言（口径）**

先定性：V1.0 里没有"抖动必须为 0"的硬性要求（最接近的 M6-07 是 V1.5 的"帧间隔均匀"）。所以严格 0 是自设的工程护栏，改它不等于放松需求。
但**护栏也要有依据**，建议按下面三条落地：

1. 口径写进 `05`：「`frames_over_2x_avg` ≤1%（12s/700 帧 ≤7，region ≤4）；无 V1.0 硬性要求，属工程护栏」；
2. 补**产品级**断言：成片重复帧占比 ≤1%（`frames_duplicated / frames_encoded`）。采集侧一次单帧卡顿最终表现为一帧重复，这才是用户能感知的量；
3. 保留 INFO 实测值（每轮记录 4/700 这类原始数字），连续两轮上升即触发排查。

**不建议标 BLOCKED**：4/700 在共享会话下是可测的真实信息，标 BLOCKED 等于把它藏起来。

**F3 · `{index}` 的语义是"第一个空位"而非"递增计数器"（提示）**

`main.cpp:252-254` 的循环把 `{index}` 与避让合并：从 1 开始找第一个不存在的。好处是天然不覆盖；代价是**删掉 `_001` 后下一次会复用它**，与"序号递增"的字面预期不同。
建议在 01/05 注一句「`{index}` 取第一个可用序号，保证不覆盖，不保证单调」，避免以后被当成 bug 报。

**该记的正面**：子句级覆盖模型（66 → 116 子句）把"有卡即通过"这个最危险的盲区堵住了，而且他们真的做了红测（拿掉卡看 C8 是否红）。这是轮 26 那条"红-绿"规则第一次用在**流程本身**上，比用在一个断言上更有价值。

### 验收标准

**自动化（计入 PASS）**
1. `ui_region.ps1`：拖拽选区 → 录制 → 成片分辨率 = 选区（偶数对齐）；预设比例误差 ≤1px；
2. `ui_preflight.ps1`：磁盘不足（`--disk-stop-mb` 注入）/ 音频设备不可用 / 采集源不可用 / 编码器不可用 四种 → 阻止 + 原因 + 无 `.part`；四项耗时各 ≤500ms；
3. G4 全链路：热键开始 → 60s → 热键停止 → 3s 内可播；`state_sequence` 完整；无残留；
4. 全部回归：`ui_smoke` 64、`g4_elapsed` 13、`g4_channel` 52、`g4_control` 32、`g5_*`、`g3_*`、`g1` 40、`g2` 18、契约 8/8、覆盖表 up to date。

**人工（单列）**
- 覆盖层视觉、框选跟手程度、预设按钮布局、自检失败提示文案 —— 截图 + 步骤。

### 注意事项

1. **500ms 预算不能靠 spawn recorder 完成**：仅启动就要 ~450ms。建议 UI 侧做"快检"（`GetDiskFreeSpaceEx`、`EnumDisplayMonitors`、`IMMDeviceEnumerator` 端点枚举、上次成功编码器缓存），真正失败由 recorder 的 `exit 6/12/13` 兜底并把原因回传给 UI 显示。两边各管一段，别互相等。
2. **区域选区的 DPI**：`GetDpiForWindow` + `LogicalToPhysicalPointForPerMonitorDPI`，否则 150% 缩放下框选错位（M6-06 一直是 BLOCKED，本轮至少保证单屏正确，跨屏限制写进 HANDOFF）。
3. 选区尺寸在传给 recorder 之前就做偶数对齐，别让 recorder 再改一次——否则 UI 显示 801×601、成片 800×600，用户会以为出错。
4. `--region` 已有后端支持，本轮只做 UI 侧；**不要顺手改采集优先级**。
5. G4 关闭需要 05 的门判据逐条对齐，缺一条就写"有条件"，不要口头"基本可用"。

### 通过判据
`ui_region` + `ui_preflight` 全绿 + G4 四条判据全部有实测数字 + 全部回归零失败 + 契约 8/8 + 双构建零告警 + 无残留进程。

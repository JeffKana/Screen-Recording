## 3. 三个发现

**F1 · M2-09 被"卡内收窄"，但覆盖表按整条记了"有卡"**

任务卡写的是「M2-09 录制计时与成片时长差 ≤0.5s；暂停期间计时冻结」——只取了半条。
01 的原文还有「**剩余时长随写盘速度动态刷新，误差 ≤15%**」，UI 里没有这个显示（`src/app/main.cpp:296-305` 只格式化 elapsed）。

问题不在实现（我这轮没要求做剩余时长），在**登记**：`docs/09` 把 M2-09 标成"有卡"，C8 因此不再要求它挂账。一条 V1.0 需求就这样静默蒸发了。
修：覆盖表增加「卡覆盖范围（整条/子句）」列；子句型要求同样要挂账；C8 按"子句覆盖"判定，而不是"有卡即过"。

归因说明：卡是我批的切片，缩范围属规划侧责任，**不记在执行者头上**；但覆盖表必须改，否则下一轮 C8 就会用同一口径放过它。

**F2 · 36fps 是环境上限，不是 WGC 的问题——别据此改采集优先级**

同一个会话、同一时刻，我用 `srprobe capture --stimulate` 分别跑两个后端：

```
wgc  : frames=179  fps_actual=35.65  frames_over_2x_avg=0  chain_trace=wgc:ok
dxgi : frames=179  fps_actual=35.66  frames_over_2x_avg=0  chain_trace=dxgi:ok
```

**两者一模一样。** 机器上还装着 `OrayIddDriver Device`（远程/投屏虚拟显示器），物理面是 Intel UHD 770 @60Hz。也就是说当前会话里，无论走哪条路径都只能拿到约 36fps。

如果按原设想去评估「WGC 优先改 DXGI 优先」，会用一个错误信号做一次不必要的架构改动——而 G3.5 测到的 WGC 58.49fps 说明它在正常会话下并不慢。

正确处置：给 g2 加**环境判定**——`--stimulate` 下两后端都 <55fps 且彼此差 ≤2fps 时判 **SKIP（环境受限）**，与 D-09 的 `dwm_throttled` 同类；只有在活跃本机会话下两后端出现显著差异，才谈优先级。

**F3 · README 数字过期**

`README:165` 仍写「`ui_smoke` 24/24」，实际 30/30。不影响功能，但"文档是唯一事实源"这条一旦松，下一次评估就得靠猜。同类小事建议一次扫干净（08 §21 与 07 的 27 行里 M2-09 也记成了 PASS，一并改成 PARTIAL）。

**该记的正面**：D-39 的改法是对的（以 begin 为基准、暂停锚定、恢复扣累计），而不是给 elapsed 打个补丁；热键冲突的处理链完整（注册失败→状态栏+托盘+日志→不阻断其它热键）；「运行中改 INI 1s 内热更新」这条超出了任务卡要求，属于主动想到了 UI 的实际使用方式。

## 4. 轮 28 指令（UI-2：主窗口、剩余时长、保存路径与命名）

### 目标
把"能录"变成"能按用户意图录"：看得见剩余时间、选得了存哪、命名可控。**G4 仍不关闭**（自检/区域在轮 29）。

### 范围与优先级

| 优先 | 项 | 具体要求 | 验收标准 |
| --- | --- | --- | --- |
| **P0** | M2-09 补齐 | 剩余可录时长显示，随磁盘与码率刷新 | 与 `(free − stop) / (bitrate/8)` 估算差 ≤15%；写盘过程中刷新（≥1 次/秒） |
| **P0** | M5-01 保存路径 | 目录选择 + 可写探测 + 持久化 | 选只读目录当场拒绝并给原因（复用 M8-06 语义）；重启后保留 |
| **P0** | M5-02 命名模板 | `{date}`、`{time}`、`{index}`、自定义前缀；默认 `SR_{date}_{time}` | 同一秒连录两次 → `_001`/`_002` 且都可播（05 AC-10） |
| **P0** | M2-08 悬浮工具条 | 置顶、可拖动、显示计时、暂停/恢复/停止、一键隐藏 | 工具条按钮与快照一致；录制中不遮挡选区（可隐藏）；拖动位置重启保留 |
| **P1** | g2 环境判定（F2） | 两后端 `--stimulate` 差值 ≤2fps 且 <55 → SKIP | g2 在虚拟显示会话下 14 PASS / 2 SKIP；真实会话仍按 FAIL |
| **P1** | 覆盖表子句化（F1） | 加「覆盖范围」列；C8 按子句判；M2-09 补挂账 | `coverage_report --check` 通过且 M2-09 显示"子句覆盖" |
| **P1** | 文档校正（F3） | README 30/30；07 轮 27 的 M2-09 改 PARTIAL | 无过期数字 |

### 验收标准

**自动化（计入 PASS）**
1. `ui_window.ps1`：设置路径 → 录 3s → 成品落在指定目录；命名模板展开正确（含 index 递增）；
2. 只读目录被拒 + 原因可见 + 不留碎片；
3. 剩余时长误差 ≤15%（对比脚本自算的 `(free−stop)/bitrate`）；
4. 悬浮条按钮状态与 `state_sequence` 一致（通过日志/快照断言，不做屏幕识别）；
5. 全部回归：`ui_smoke` 30、`g4_elapsed` 13、`g4_channel` 52、`g4_control` 32、`g5_*`、`g3_*`、`g1` 40、`g2` 14+2SKIP、契约 8/8。

**人工（单列，不计入 PASS）**
- 悬浮条拖动/置顶/隐藏、路径选择对话框外观、命名预览 —— 截图 + 步骤。

### 注意事项

1. **剩余时长的公式只能有一份**：把 `(free − stop) / (bitrate/8)` 抽到 `src/core/util/`（纯数学，无平台依赖），`StorageGuard` 与 UI 共用；两边各写一遍迟早会漂。
2. **不要让 UI 去算"能不能写"**：可写性一律以 recorder 的 `record_exit=13` 为准，UI 只做提前提示，避免两套判断。
3. 命名模板在 **UI 侧展开**，recorder 只接收最终路径——这样不用改 IPC 契约。展开后仍要经过 `FindFreePath` 避让，双层保险。
4. 悬浮条必须用 `WS_EX_TOPMOST` + `WS_EX_NOACTIVATE`，否则点按钮会把焦点从被测窗口抢走（录制窗口采集时尤其明显）。
5. 本轮人工项会变多（对话框、拖动、置顶），务必与自动化分开统计；上一轮 4 张截图的做法保持。

### 通过判据
`ui_window.ps1` 全绿 + 全部回归零失败 + 契约 8/8 + 双构建零告警 + 无残留进程 + 人工清单截图齐备。

## 2. M1-08 的实现要点（别做成"拉伸凑数"）

1. 采集源已经在跟踪窗口尺寸（WGC 的 `item.Size` 变化会触发重建），**先确认现状**：是"没跟"还是"跟了但比例处理错"。
2. 比例策略：`fill`（等比填满 + 黑边）/ `stretch`（拉伸）；默认 `fill`，写进 INI 与设置页。
3. 偶数对齐仍在 UI/启动参数层做，采集层不要二次改尺寸。
4. 拖动过程中的中间尺寸会触发多次重建，**必须限流**（例如尺寸变化 <2px 忽略、重建间隔 ≥200ms），否则会出现黑帧抖动——这正是 M1-08#1 要验的「画面始终完整」。

## 4. 注意事项

1. `card_consistency_check` 不要做成"关键词黑名单"就完事：真正的判据是「状态行说已实现、正文出现『未实现/保持』且未标注历史」→ 报冲突。宁可少量误报，也别漏。
2. M1-08 的拖动重建会放大采集抖动，**先量后调**：记录重建次数与丢帧数，再决定限流阈值，不要凭感觉设 200ms。
3. M1-27 的提示文案要克制：我们**录不到**提权窗口的内容，文案只能说「该区域将为黑屏，建议以管理员身份重启」，不能暗示"开了就能录"。
4. 本轮**不要**再动覆盖合并规则；它刚稳定，改一次要重跑全部 116 子句的审计。
5. `docs/09` 的「87→85 属纠偏」说明保留，别被 `--write` 冲掉（生成器已支持，验证一次）。

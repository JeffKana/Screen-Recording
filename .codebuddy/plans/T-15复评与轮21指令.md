## 3. 五个发现

**F1 · 倒计时放在了文件创建之后，取消在当前结构下做不出来（结构性）**

`muxer.Open()` 在 `RecordingSession.cpp:130`，倒计时在 `:225`。也就是说倒计时期间 `.part` 已经存在、目录已经创建、采集已经在跑（`:82`）。
所以 `:223` 那句注释「倒计时期间不采集、不写盘」与代码不符；更关键的是——加取消时，删掉 `.part` 才不违反「不产生任何文件」，而删除本身又要考虑崩溃残留，这是自找的复杂度。
指令给的顺序是 **倒计时 → PrepareOutputPath → muxer.Open**，本轮反了。

**F2 · 音轨完全没有断言（指令点名的「最有价值断言」被漏掉）**

`g3_control.ps1` 17 条里没有一条读音频流。我手工测了末包 PTS：

| 文件 | 视频末 PTS | 音频末 PTS | 尾部差 |
| --- | --- | --- | --- |
| `output/same.mkv`（轮 19，无暂停） | 1.999 | 1.904 | **95ms** |
| `control/fixed.mkv`（无暂停） | 7.999 | 7.918 | **81ms** |
| `control/pause_wgc.mkv`（暂停 3s） | 3.999 | 3.761 | **238ms** |
| `control/pause_dxgi.mkv`（暂停 3s） | 3.999 | 3.854 | **145ms** |
| `control/pause.mkv`（暂停 4s） | 5.999 | 5.712 | **287ms** |

结论：`Reset()` 生效（没有出现 +4s 的静音），但**暂停后尾部差从 ~90ms 涨到 145~287ms**，逼近 300ms。这是真实存在的偏差，而用例看不见它。

**F3 · 恢复失败会静默成功（D-28）**

`:292`（采集 Start 失败）、`:310`（拿不到 D3D11 设备）、`:322`（转换器重建失败）三处都是 `break`，跳出后照常 flush → Close → CommitOutput → **`return 0`**（`:519`）。
而 `main.cpp` 只在 `code != 0` 时打印 `error=`，所以现场是：录制中途哑火、成片偏短、退出码 0、日志里一句 error。这与 T-16 的「编码器失败/设备丢失」注入直接冲突——会得到假 PASS。

**F4 · 暂停只支持一次，且「暂停」在产品路径里不是状态**

`pause_pending = false;`（`:350`）之后再也不进暂停分支，UI 上「暂停→恢复→再暂停」第二次无效。
更根本的：`RecordingSession` 完全没接 `RecorderStateMachine`（只有 G1 的 `SessionServer` 用），暂停只是本地 `bool paused`。M2-10 的状态机在 G1 判 PASS 是**单元级**结论，产品路径至今没有状态源。

**F5 · 裁定没有落到文档（一致性）**

10 分钟前刚裁定的锚点是 `M2-02 / M2-04 / M7-02`，但：
- `g3_control.ps1:1` 头注释写「(M2-03 / M2-04 / M2-05)」；
- `docs/07` 轮 20 三行全是 `M2-03/04/05`；
- `docs/08 §15` 表里 5 行全写 `M2-03`/`M2-05`。
另外 `tasks/G5/S2-001/` 只有 `EVIDENCE.md`，缺 TASK/SELFTEST/HANDOFF；跨域写入了 `src/compositor/Nv12Converter.cpp` 却没有任务卡声明该域。

## 5. 轮 21 修正指令

**任务**：T-15 补正（关 M2-04 取消、补音轨断言、堵 D-28、接状态机）
**执行者**：S1（`src/recorder/`）；跨域 `src/recorder/` + `src/ipc/` 不涉及
**计划轮次**：1　**截止判据**：下述全绿，且 `g3_control` ≥ 24 PASS

### P0-1 倒计时前移 + 取消（关 M2-04）

- 把倒计时整块移到 `PrepareOutputPath` **之前**（且在任何目录/文件创建、采集启动之前）。
- 新增 `--cancel-at <秒>`（确定性注入）与控制命令 `Cancel`，取消时：**exit 14**、输出 `cancelled=1`、不写 `output=`。
- 断言：`record_exit=14`；目标目录**不存在**；无 `.part`；`paused_ms=0`；倒计时期间无 `[record]` 之外的文件系统副作用。
- 删掉 `:223` 那句与事实不符的注释，或让代码真的满足它。

### P0-2 音轨对齐断言（补 F2）

- `g3_control.ps1` 增加：`视频末 PTS − 音频末 PTS ≤ 300ms`（对暂停与非暂停各一条），并记录基线 81~95ms。
- 若暂停后尾部差 > 300ms，先查 `audio_timeline->Reset()` 之后的首次 `Pull` 与 `audio_source->Start()` 的空档，再决定是补静音还是延后收尾。

### P0-3 恢复失败不得静默（关 D-28）

- `:292/:310/:322` 三处 `break` 改为：置 `resume_failed=true`，收尾后 **`return 15`**（新增错误码，写入 CONTRACT §6 与 main 的退出码表）。
- 断言：新增 `--fail-resume` 注入（强制一次 `Start` 失败），要求退出码 15、成品仍可播、已录内容不丢、`resume_failed=1`。

### P0-4 接入状态机（补 F4 的产品侧）

- `RecordingSession` 持有 `RecorderStateMachine`，按 `Start → PreflightOk → CountdownElapsed? → Recording ⇄ Paused → Stop → FinalizeDone` 驱动；非法命令走 `Rejected` 并计数。
- 输出 `state_sequence=Idle,Preflight,Countdown,Recording,Paused,Recording,Stopping,Idle`。
- 断言：暂停用例的序列与上句逐字一致；`Stop` 后再 `Pause` 必须 `Rejected`。
- 支持**多次暂停**：`pause_pending` 改为一组计划或由控制命令驱动，用例补「暂停→恢复→再暂停」。

### P1 文档与证据（补 F5）

- 锚点统一 `M2-02 / M2-04 / M7-02`：改 `g3_control.ps1` 头注释、`docs/07` 轮 20 三行、`docs/08 §15`。
- 用例改名 `g4_control.ps1`（门归属 G4），并在 README 常用命令里登记。
- `tasks/G5/S1-002/{TASK,EVIDENCE,SELFTEST,HANDOFF}.md`；`tasks/G5/S2-001/` 补齐三件并**声明** `src/compositor/Nv12Converter.cpp` 的跨域写入理由。

### 硬边界

1. 控制通道（`PipeConnection::TryReceive` + `--control-pipe` + srctl）本轮仍不做，但必须在 `08 §15` 与台账显式登记为「T-09 前置」，不得默认视为已完成；P0-4 已提供状态源，T-09 接入时不需要再改主循环。
2. P0-1~P0-4 任一项在一轮内未达成 → 停，不进入 T-16；不得用放宽断言的方式收尾。
3. 若恢复失败注入在 3 次尝试内无法稳定复现 → 只保留退出码改造并记录「注入不成立」，不得标 PASS。

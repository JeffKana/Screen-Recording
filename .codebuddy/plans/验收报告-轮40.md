## 2. 唯一的问题：`g5_storage` 的 M8-05 断言会间歇性假失败

我第一次跑：

```
FAIL m8-05-01-estimate-error-20pct — 估算=0s 实测口径=0s 误差=100.0%
     （实测码率=0 B/s, free=0 B, bytes_written=0）
```

后两次跑：

```
PASS — 估算=32,232s 实测口径=32,283s 误差=0.2%（码率 772,771 B/s）
```

读码确认根因：

```187:194:verify/cases/g5_storage.ps1
$estSeconds = [double](Field $estOut 'estimated_record_seconds')
$freeBytes = [double](Field $estOut 'disk_free_bytes')
$bytesWritten = [double](Field $estOut 'bytes_written')
...
$errorRatio = if ($expectedSeconds -gt 0) { ... } else { 1.0 }
```

`$estOut` 为空时（上一段录制进程未完全退出 → 单实例锁挡住本次启动 → 输出里没有这些字段），四个变量全取默认 0，`$errorRatio` 落到 `1.0`，于是**用"没取到数据"算出了一个 100% 的误差**。
这跟 D-58（用错误的时间基算漂移）是同一族：**拿缺失/错误的输入直接算结论**。

产品侧没问题（两次成功跑误差 0.1~0.2%），问题在用例的取数前置与失败语义。

## 4. findings

**R1 [Required] `g5_storage` M8-05 假失败**
- 定位：`verify/cases/g5_storage.ps1:186-194`
- 现象：字段缺失时用 0 计算，得出"误差 100%"的假失败（3 次 1 次）
- remedy：① M8-05 段开跑前 `Clear-SrProcesses` + 等 ≤2s 确认无残留（单实例锁）；② 断言前校验 `estimated_record_seconds`/`disk_free_bytes`/`bytes_written` 均非空，缺失则重试一次，仍缺失就报"数据未取到"（SKIP），**不要用 0 参与误差计算**
- 归属：执行者

**R2 [FYI] M1-27 的 BLOCKED 要写进挂账理由**
- 现象：SKIP 理由只在用例输出里，`docs/09` 的 M1-27#1 挂账理由仍是旧的"未开工"
- remedy：改为"提示/入口已实现；黑屏需在开启安全桌面的机器复测（本机 ConsentPromptBehaviorAdmin=0 不可复现）"
- 归属：执行者

**R3 [FYI] M8-03#2 的历史误标是第二例自查发现的"结论宽于证据"**
- 现象：`critical` 无人消费、阈值非 500MB，却长期标"已实现"
- 处置：已在 `docs/08:532` 加轮 40 更正注；记录在案，说明"文档里的已实现"不能当证据，只有用例能

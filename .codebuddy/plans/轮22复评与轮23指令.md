## 3. 四个发现

**F1 · ER-02 的判据在短录制上是空的（判据设计问题，我的指令也有责任）**

`minDur = max(0.5, killAt/1000 − 10)`。强杀点在 8s 时下界变成 `0.5s`——只要恢复出半秒内容就算通过。
需求级「丢失 ≤10s」必须保留，但它对 5~8s 的用例不构成约束。真正有信息量的是那行 `INFO loss=3.03s`，而它是打印，不是断言。

建议双阈值：需求级 `loss ≤ 10s`（必须）+ **回归护栏 `loss ≤ 5s`**（工程指标，注明来源是实测基线的 1.5 倍，不是需求）。护栏可以随实现改进收紧，需求级永不动。

顺带一个观察：编码器侧有约 3s 的包积压（8s 强杀只捞回 4.97s），所以崩溃丢失的下界目前是「未落盘簇 1.5s + 编码器缓冲 ~1.5s」，不是 1.5s。要压到 2s 内，得提高 drain 频率，属 T-17 的优化项。

**F2 · `--fail-encoder` 是自证：断言匹配的正是注入自己编的字符串**

`RecordingSession.cpp:153-158` 在 `encoder.Open` **之前**短路，并自己写出 `"no usable video encoder (injected by --fail-encoder)"`；用例断言 `$out -match 'no usable video encoder'`。
结论只对「退出码 6 + 不产生文件」成立；`MfVideoEncoder::Open` 里「硬编与软编都枚举不到」的真实分支**没跑**，真实错误文案、清理路径都未验证。这和 D-27 同型：测量与被测同源。
修法：把注入下沉到 `MfVideoEncoder::CreateTransform(false)` 失败，让真实的「双 MFT 皆不可用」分支跑起来（3 行）。

**F3 · D-32（新）：恢复产物会覆盖，且 `.part` 不消解**

实测：`--repair` 产出的 `rec.mkv.recovered.mkv` 留下后，`.part` 仍在；再跑 `--scan` 同一目录：

```
scanned=1
repairable=1
suggested_output=...\rec.mkv.recovered.mkv
```

而 `MkvRecovery::Repair` 用 `std::ofstream out(out_path, std::ios::binary | std::ios::trunc)`（`MkvRecovery.cpp:307`）——**同名即覆盖**。
后果：① 每次启动都会再次提示「可修复」，用户重复修复；② 第二次修复会静默覆盖上一次的恢复产物（用户可能已经打开或移动过它）。这与 D-24 是同一族问题的另一处，只是发生在 `src/resilience/`。

**F4 · 台账被空行截断**

`docs/07` 第 37、40 行是空行，把表切成 3 段；Markdown 里空行即表尾，后面 11 行会渲染成纯文本。`contract_check` 只看表头 7 列，所以没报。
另外角色标签第 3 轮仍错：D-30 改的是 `src/mux/MkvWriter`（**S4** 域）与 `src/recorder`（S1），却记成 S2。

**该记的正面**：D-30 的定位很准（暂停不落盘 → 恰好一簇 1.5s，实测 3.44→4.97 对得上）；ER-04 阈值改为按轮重算，识别出了「测到的是 exit 12 而不是写入路径」；把 3.5s 判据退回需求原文 10s，这个决定是对的——阈值只能来自需求。

## 5. 轮 23 指令（T-16b：M8-06 后半 + 恢复幂等 + 三个整改）

**计划轮次：2　截止判据：下述全绿**

### P0-1 `--fail-write-after <N>`
在 `MkvWriter` 内部计数，第 N 次 `WriteVideo/WriteAudio` 返回 false（而不是在外层伪造），走真实的 `write_errors → fatal 15` 路径。

### P0-2 `--fallback-dir <dir>`（M8-06 后半，本轮的核）
fatal 15 时：Close 封装 → 用 `MkvRecovery::Probe/Repair` **截断到最后一个完整 Cluster** → 提交到 fallback 目录 → 输出 `fallback_path=` → **退出码 16**。
判据：成品可播、时长 ≥ 故障前已落盘时长 − 1.5s、原目录无 0 字节、`fallback_path` 存在且可解、`exit=16`。
**硬边界**：必须是真实修复产物，直接 copy `.part` 不算（截断在簇中间，不可播）；若 `Repair` 在 fallback 目标上失败，判 BLOCKED 并写原因，不得返回成功。

### P0-3 C11 后端漂移（真实注入）
注入「恢复时首选后端不可用」，让链真实切到下一后端：断言 `backend_changed=1`、WARNING 日志存在、录制不中断、成片可播、时长不变。
**硬边界**：造不出真实降级就判 BLOCKED，不得伪造标志。

### P0-4 D-32 恢复幂等
- `Repair` 输出改为**同名避让**（复用 `OutputPath` 的 `FindFreePath` 思路，或直接抽公共函数）；
- 修复成功后把源 `.part` 改名为 `<name>.part.repaired`（保留证据、退出扫描视野）；
- 断言：二次 `--scan` 该目录 **不再出现** `repairable=1`；二次 `--repair` 不覆盖已有 `recovered.mkv`（新文件名为 `_001`）。

### P0-5 两个判据整改
- ER-02 加回归护栏 `loss ≤ 5s`（需求级 10s 保留，注释说明两者性质不同）；
- `--fail-encoder` 注入下沉到 `MfVideoEncoder` 内部，让真实「双 MFT 皆不可用」分支跑起来。

### P1 台账
- 去掉表内空行（表必须连续，否则渲染断裂）；
- 角色按域：`src/mux` → S4、`src/recorder` → S1、`src/compositor` → S2、`src/resilience` → S6。

## 2. F1 的取证要求（别用"负载抖动"结案）

1. 每次录制保留 `metrics` 全量行，标注 `capture_fps / encode_fps / dropped`；
2. 逐秒表要能定位到**具体秒号**，并标出该秒是否含关键帧（按 GOP=2×fps 推算，或用 `--dump-es` 校验）；
3. 关键帧秒的字节分解：`keyframe_bytes`、`filler_bytes`、`other_bytes`；
4. **静态桌面必须是最小化干扰的**（别开浏览器放视频），否则测的是运动源的另一种情形。

如果最后证明是"filler 按帧补偿、没按秒结算"，修法就是把补偿口径从帧改到秒——**别去动 CBR 模式本身的实现**。

## 4. 注意事项

1. **不要把 F1 和 F2 混在一个改动里**：F2 是改用例，F1 可能改产品。混在一起，回归红了分不清谁的责任。
2. 如果 F1 定性后决定回退 M3-04#1，**照做**，并在 `docs/09` 顶部加变更说明；不要为了保住 104 这个数字拖着。
3. `g5_format` 的 10 条 FAIL 刷屏本身也是问题：它会让真正的产品失败淹没在噪声里（这次就是）。
4. 本轮不要再动 `g5_storage` 的口径；它刚稳定（14/14，双断言）。
5. 矩阵补齐只填能测的；测不了的继续标"未测"，别用"降级验证"覆盖整格。

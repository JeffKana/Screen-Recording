## 3. 四个发现

**F1 · 音轨那条断言的尺子偏了一帧（重要）**

`video_last_pts_ms = (frames_encoded-1)*1000/fps`（`RecordingSession.cpp:601-603`）是**算出来的**，不是写入 muxer 的实际末 PTS。
我用 ffprobe 实测同一批产物：

| 文件 | 用例自报 diff | ffprobe 实测 diff | 少报 |
| --- | --- | --- | --- |
| `plain.mkv`（无暂停） | 48ms | **100ms** | 52ms |
| `pause.mkv`（暂停 4s） | 228ms | **264ms** | 36ms |
| `failresume.mkv` | —（未断言） | 95ms | — |

原因：真实末帧 PTS 比 `(n-1)/fps` 大一个帧周期（muxer 侧时间基偏 33ms）。后果很实际：**判据 300ms 时，真实 330ms 的偏差会被报成 ~294ms 通过**。这正是 D-06/D-07/D-27 同一类问题——尺子比被测对象更该被怀疑。方向没错，落点差一帧。
修法（3 行）：在 `drain_encoder` / flush 写盘处记录真正提交的末 PTS，用它取代推导值；然后把两条阈值改成实测口径（预期 100ms / 264ms）。

**F2 · `docs/08 §15` 自相矛盾**

`315` 行仍写「`g3_control.ps1`：17 PASS」，表内 5 行仍标 `M2-03`/`M2-05`；而 `328` 行写「本轮已统一」。
同一节里一半是新口径、一半是旧口径，且引用的文件已不存在（改名 `g4_control.ps1`）。

**F3 · 台账乱序 + 改评审判定（流程）**

`docs/07` 现在是 `18, 19, 20, 20, 20, 21, 21, 19, 19, 19`：
- 轮 19 的三行（我的 E1/S1/V1 记录）被排到轮 21 之后；

## 4. 你提的裁定点：C11 后端漂移要不要现在加注入

**不加，并入 T-16，但要登记成子项。** 理由：

1. 链路降级的**能力**已由 G3.5 的 `chain_trace=wgc:fail → dxgi:ok` 验证过；C11 缺的只是「恢复路径触发降级」这一个组合，不是新能力。
2. T-16 的 ER-09（分辨率变更）/ER-08（设备丢失）本来就要人为制造采集中断，届时降级必然发生，`backend_changed=1` 顺带被验证，不需要为测试单独造开关。
3. 不登记就会出问题：将来读者看到 C11 会读成「降级路径已验证」。所以必须写成「本轮仅证明未漂移，漂移路径待 T-16 子项」。

裁定：**不加开关，登记为 T-16 子项**，判据写「恢复时强制后端不可用 → `backend_changed=1` + WARNING 日志 + 录制不中断 + 成片可播」。

## 5. 轮 22 指令（T-16a 故障注入矩阵）

**先说一个规划错误**：`08 §11.2` 把 T-16 记为 `ER-01/04/08`，括号却是「磁盘满、路径不可写、编码器失败」——对不上。

| 05 编号 | 真实含义 | 可否自动化 |
| --- | --- | --- |
| ER-01 | 录制中**物理断电** | 不可。用 ER-02（`taskkill /F`）作代理，并在结论里写明「代理，非 ER-01」 |
| ER-04 | 磁盘填到耗尽 | 可（`--disk-stop-mb` 注入到「当前可用−2MB」，与真实耗尽同分支） |
| ER-06 | 路径只读 / 不可写 | 可（只读目录 + 录制中失效） |
| ER-08 | **TDR**（GPU 压测） | 需 GPU 压测且 M8-09 属 V1.5 → 本轮**挂账**，不得算通过 |
| M8-08 | 编码器初始化失败回退 | 可（`--backend`/编码器无效值触发回退与全失败两种结局） |

本轮锚点改为：**ER-04、ER-06、M8-08 各 3 次 + ER-02 作 ER-01 代理 3 次**；ER-08 挂账。

### 步骤

**P0-0 修正 F1 的尺子（前列，3 行）**
- muxer 写盘处记录实际末视频 PTS，替换 `(frames-1)/fps`；`g4_control` 两条阈值改实测口径并重跑，预期 100ms / 264ms。
- 复核：`g4_control` 32/32。

**P0-1 ER-04 磁盘耗尽 ×3**
- 每次：`--seconds 30 --disk-stop-mb <free−2MB>`，断言 `disk_stop=1`、`wall<15s`、成品可播、无 `.part`、无 0 字节文件。
- 三次结果必须一致（不稳定项按 06 双倍扣分）。

**P0-2 ER-06 路径不可写 ×3**
- 变体：① 目标目录设为只读；② 目标指向普通文件下的子路径；③ 录制中把 `.part` 所在目录置为只读（验证写失败传播 → `write_errors>0` → exit ≠ 0 且成品可播或明确失败）。
- 断言：开录前拒绝时 `record_exit=13` 且无碎片；录制中失效时退出码非 0、已录内容可播（走 D-28 收尾路径）。

**P0-3 ER-02 强杀 ×3（ER-01 代理）**
- 分别在第 3s、暂停窗口内、收尾前强杀；每次 `--scan` 得 `repairable=1`，`--repair` 后时长 ≥ 原时长−10s、可解码、含 video+audio。
- 结论措辞固定为「ER-02 代理，不等同 ER-01 断电」。

**P0-4 M8-08 编码器失败 ×3**
- ① 指定不可用编码器 → 回退软编成功（`encoder=mf-h264-sw`）；② 强制全部失败（无效后端/参数）→ 明确错误码 + 不留 0 字节文件。
- 断言 `code` 与 `encoder=` 字段，两次结果一致。

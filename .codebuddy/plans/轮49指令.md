## P0-2 M3-09#1 faststart（moov 前置）

现状：`moov` 后置可播，但不符合「faststart」判据。

判据：

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | box 偏移 | `moov` 起始偏移 **<** `mdat` 起始偏移 |
| 2 | `ffprobe` | 可播，时长/帧数与录制一致（±0.2s） |
| 3 | 全解 | `ffmpeg -v error -f null -` 零 error |
| 4 | 二次读取 | 从文件前 64KB 内即可解析出 `moov`（说明未后置） |
| 5 | 回归 | 非 faststart 路径（如 `--no-faststart` 若实现）仍可播 |

实现建议：先写完 `mdat` 再回填 `moov` 需要两遍写或内存缓冲；**推荐内存缓冲 moov（几十 KB 级）+ 一次落盘**，比 seek 回填简单。注意 `.part` 语义：缓冲在内存期间崩溃 → `.part` 里只有 `mdat`，**必须仍能被恢复流程识别为不可修复并保留**，不许产出"可播但时长错"的文件。

## P0-3 M3-09#2 MKV 多音轨

- `MkvWriter` 的 `audio_info_` 单成员改容器（vector），TrackNumber 按轨分配，`WriteAudio(track_idx)`；
- 入口：`--audio-tracks` 或复用现有混音器，**具体形态你定**，但必须能产出至少 2 条音轨；
- 判据：`ffprobe -show_streams` 两条 `codec_type=audio`、各自可独立解码、轨道时长与视频差 ≤100ms；
- 回归：单音轨 MKV 逐字节行为不变（`g3_playback` 11/0、`g3_recovery` 9/0）。

## 注意事项

1. **faststart 与 `.part` 语义会打架**：moov 在内存里时崩溃，`.part` 缺 moov。要么先把"临时 moov"落到 `.part` 尾部再回填，要么明确该 `.part` 判为不可修复且保留——**二选一写进 HANDOFF**，不许静默丢。
2. 多音轨别改 IPC：轨道选择属本地参数，不塞进控制通道。
3. UI 改扩展名时注意 `M5-02` 的模板变量 `{date}{time}` 拼接顺序，别把 `.mp4` 拼在 `_001` 前面。
4. 本轮仍不做 MP4 恢复（V1.1），别顺手开这个口子。

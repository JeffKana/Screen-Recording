## 3. 三个遗留（不阻塞本轮，但必须处理）

**F1 · D-39：`session_elapsed_ms` 在暂停期间继续增长**

证据就在你们自己的输出里：

```
state=Recording  elapsed_ms=1558
state=Paused     elapsed_ms=1589   ← 进入暂停
state=Paused     elapsed_ms=2209   ← 暂停 620ms 后，elapsed 涨了 620
```

`make_snapshot` 用的是 `clock.ElapsedMs(begin, now)`，即墙钟。01 的 M2-09 要求「录制计时与成片时长一致（误差 ≤0.5s）」——UI 一旦把这个字段绑到计时器上，暂停时秒表会继续走，暂停 10 分钟就偏差 10 分钟。

修：快照用**媒体时间**（`frames_encoded × 帧时长` 或 `timeline` 累计），并加断言「暂停 3s 前后 elapsed 不变」。

**F2 · D-40：三个用例只认 `bin\<exe>`，MSVC 布局下直接 FAIL**

我实测：

```
g1_walk -BuildDir build-msvc   → FAIL: missing ...\build-msvc\bin\sr-recorder.exe
g2_walk -BuildDir build-msvc   → FAIL: missing ...\build-msvc\bin\srprobe.exe
g3_playback -BuildDir build-msvc → FAIL: missing ...\build-msvc\bin\sr-recorder.exe
```

`g1_walk` / `g2_walk` / `g3_playback` 没有 `bin\<Config>` 回退，而 g4/g5/g3_output 等都有。于是「全绿」实际是用 MinGW 产物跑出来的，与 CONTRACT 规定的 MSVC 主发布链不一致。
修：三处统一成与 `g4_channel` 相同的解析顺序（`bin\<Config>` → `bin\`），并在 README 注明默认 `-Config Release`。

**F3 · 计时暂停也受 900s 超时约束**

`--pause-duration 1200` 配默认 timeout=900，会在第 900s 直接收尾，而不是按计划恢复。这可能是想要的行为（"没有 UI 就不能停太久"），但对"定时暂停 20 分钟"是误伤。请在 CONTRACT §18.3 写明「计划暂停 > timeout 时以 timeout 为准」，或对计时暂停豁免。

**顺带**：覆盖数我这边算出 **34 覆盖 / 32 待切片**，你们报 35/31。差 1 条，正好说明覆盖表必须由工具生成、不能手数。

## 5. 轮 27 指令（UI-1：骨架 + 托盘 + 热键）

### 目标
让录制第一次有"壳"：托盘能开录/停录、热键在失焦时可用、状态与成片一致。**不追求好看，只追求闭环可验。**

### 范围与优先级

| 优先 | 项 | 具体要求 | 验收标准 |
| --- | --- | --- | --- |
| **P0** | D-39 计时语义 | `session_elapsed_ms` 改媒体时间 | 暂停 3s 前后 elapsed 不变（±50ms）；恢复后继续累加；与成片时长差 ≤0.5s |
| **P0** | 进程骨架 | Win32 隐藏窗口 + 消息循环 + 单实例；无三方依赖 | 二次启动激活已有实例（M2-12 与 UI 复用）；进程退出无残留 |
| **P0** | 托盘 + 菜单（M2-07） | 开始/暂停/停止/打开目录/设置/退出；状态置灰 | 菜单项状态与 `state_sequence` 末态一致；点击行为与热键一致 |
| **P0** | 全局热键（M2-05） | `RegisterHotKey`，默认 `Ctrl+Alt+F9` 开始/停止、`Ctrl+Alt+F10` 暂停/恢复 | 切到浏览器后按热键仍生效；响应 ≤200ms（打点实测） |
| **P0** | 热键自定义与冲突（M2-06） | 注册失败识别占用并拒绝保存；持久化 `%LOCALAPPDATA%\ScreenRecorder\hotkeys.ini` | 占位组合（先用一个已知被占的键）→ 提示并拒绝；改后立即生效且重启保留 |
| **P0** | 驱动录制 | UI 以 `sr-recorder --record --control-pipe` 起子进程，复用 `PipeClient` 发 Pause/Resume/Stop | 录 3s→停止→成品可播；`exit=0`；目录可打开；无残留进程 |
| **P1** | 最小化到托盘（M2-13） | 关闭按钮最小化而非退出 | 任务栏消失、托盘保留、再点恢复 |
| **P1** | D-40 + 覆盖表 | 三处用例路径统一；建覆盖表；C7 拆 C7/C8 | `g1/g2/g3_playback -BuildDir build-msvc` 全部可跑；C8 红/绿口径写进 CONTRACT |

### 验收标准（自动化 + 人工分开记）

**自动化（进 PASS 统计）**
1. `ui_smoke.ps1`：起 UI → 热键（`keybd_event` 模拟）开始 → 3s → 热键停止 → 成品可播、`exit=0`、无残留；
2. 热键响应：从按键到 `state=Recording` 的日志时间差 ≤200ms；
3. 计时显示与成片时长差 ≤0.5s（暂停 3s 场景）；
4. 冲突热键被拒 + 改为可用组合后生效 + 重启保留；
5. `g4_channel` 50、`g4_control` 32、`g5_*`、`g3_*`、`g1` 40、`g2` 16 零回归。

**人工（单列，不计入 PASS）**
- 托盘图标状态、菜单项置灰、最小化到托盘、打开目录 —— 截图 + 操作步骤，标注「人工验证」。

### 注意事项

1. **M2-01 的 1.5s 是卡线项**：spawn + 采集/编码初始化实测约 0.9~1.1s。若"按下热键→进入录制态"超过 1.5s，先量再加常驻预初始化（idle 进程），不要靠调参掩饰。
2. **UI 不得直接持有采集/编码对象**（CONTRACT §3：`src/app/` 只能依赖 core + ipc）。所有控制走管道命令。
3. 热键回调不要在里面做重活：只发命令，状态由快照驱动（M2 的"状态唯一所有权"）。
4. 托盘/热键的失败必须可见（注册失败弹提示），不能静默降级——否则"热键不灵敏"会被误判为驱动问题。
5. 本轮起，**人工验证项与自动化项分开报**，避免"全绿"再次掩盖未验证的部分。

### 通过判据
`ui_smoke.ps1` 全绿 + 全部回归零失败 + 契约 7/7（含新增 C8）+ 双构建零告警 + 无残留进程。

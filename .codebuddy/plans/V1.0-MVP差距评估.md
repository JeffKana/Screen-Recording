## 三、工程质量

**代码**
- 分层清晰：`core` 接口 → `capture/encode/mux/audio` 实现 → `recorder` 编排 → `app` 只经 IPC 指挥，UI 不持有采集对象。
- RAII/ComPtr 统一；错误用 `bool + std::string error` 返回，不抛异常；失败路径的句柄释放有专项修复史（D-33）。
- 注释质量高于平均：写"为什么"（B 帧 PTS 非单调、原地搬移代价、探测必须复用生产 Open 路径），多数带轮次编号，可追溯。

**测试**
- 十套集成用例覆盖采集/编码/封装/控制/恢复/UI；每条断言有红-绿对照的历史记录。
- 覆盖模型从"需求级"演进到**子句级三态**（已实现/有卡未实现/无卡），并按"最保守"合并——这一层是防"假绿"的关键基础设施。
- 弱点：全部依赖真实桌面与 GPU，**无法进 CI**；UI 类用例有 1/10 量级的时序抖动（已留档）。

**流程**
- 任务卡四件套 + 台账一行制 + 独立验收 + PR/CI 门禁 + 规则集（禁强推/必过检查），可追溯性良好。

## 七、后续优先级

**P0（不解决就无法发布）**
1. 轮 50 发布复核：ER 三项重跑 + 代理标注逐条核对 + 缺陷分级重列 + EX-01/M6-06 终审 + ≥1GB MP4 收尾实测。
2. 轮 51–52 长稳：LT-01 ×2（8h）、LT-02 ×2，独占窗口、同口径。
3. 真机决策：Win10 23H2 / NVIDIA / AMD / B 机——**到位则补格，不到位则由 O0 书面批准例外并公开说明**。

**P1（发布后第一优先）**
4. MP4 崩溃恢复（V1.1 前置）：`.part` 可修复 + 断点续写。
5. faststart 大文件优化（预留 moov 空间，避免收尾全量搬移）。

**P2（工程质量）**
6. `RecordingSession` 拆分；UI 用例抖动治理（失败即取证已有雏形）。
7. 硬编路径在更多机型上的真实验证（当前本机 MFT 拒 NV12）。

## 八、一句话总结

**这是一个"功能已收口、验证未收口"的 MVP**：13 个模块、1.7 万行零依赖 C++，录制主链路与异常兜底都已闭合，覆盖模型与验收流程也做到了可追溯；真正的发布阻塞不在代码，而在四台机器、两次 8 小时、和一次独立复核。

# 05 · 非功能需求与验收

> 本文回答两个问题：**「性能达标」怎么测**、**「功能可用」怎么判**。所有数值均为设计目标，判定必须同时满足「参考机型 + 测量方法 + 采样窗口」三要素。

## 2. 性能基线

### 2.1 测量方法

| 指标 | 工具 / 方法 | 采样窗口 |
| --- | --- | --- |
| 整机 CPU | 任务管理器「性能」或 PerfMon `\Processor(_Total)\% Processor Time` | 录制稳定后 10 分钟均值，前 60 秒不计 |
| 引擎内存 | 任务管理器按进程看 Recorder 的**专用工作集** | 同上，记录均值与峰值 |
| 首帧延迟 | 内部埋点：`Start` 命令时间戳 → 第一帧进入编码器时间戳 | 单次，重复 10 次取中位数 |
| 帧率达标率 | 内部统计：实际编码帧数 / 期望帧数（时长 × 配置帧率） | 全程 |
| 丢帧数 | 内部统计 M6-11 面板 | 全程 |
| 落盘速度 | 内部统计写入字节 / 时间 | 全程，取 P95 |
| 音画偏差 | 基准动作法，见 §4 | 关键时间点 |
| 停止到可用 | `Stop` 命令 → 成品文件可被播放器打开的墙钟时间 | 单次，60s 与 1h 素材各测 |

### 2.3 帧间隔抖动与重复帧（轮 29 / F2）

V1.0 没有「抖动必须为 0」的硬性要求（最接近的 M6-07 属 V1.5），
`g2_walk` 的 `frames_over_2x_avg` 是工程护栏，不是发布判据：

- **采集侧口径（display，60fps 目标）**：12s/约 700 帧允许 <1% 的单帧毛刺（≤7 帧）。
  原始值以 `INFO display_jitter_raw=x/700` 写入日志；连续两轮上升即排查。
  不把 4/700 标 BLOCKED——那是可测信息，标 BLOCKED 等于把它藏起来。
- **region（30fps 录制目标，M1-04/M3-03）**：≥30fps 即可，抖动允许 <10%（6s/约 300 帧 ≤30）；
  不与 display 的 55fps/1% 混用。DXGI 裁剪路径在共享会话下 49fps/23 属于正常范围，
  产品成片仍按 30fps 时间轴补齐。
- **产品级口径**：**成片重复帧占比 ≤1%**。采集侧一次单帧卡顿最终表现为一帧重复，
  这是用户能感知的量。由 `verify/cases/g4_gate.ps1` 在 60s、带运动源的素材上断言：
  ffmpeg 逐帧 md5，统计连续相同哈希 / 总帧数。轮 29 实测 **0/1806 = 0%**。
- 静止桌面本来就会产生大量重复帧，重复帧断言必须配运动源（`verify/cases/stimulus.ps1`），
  否则测到的是桌面静止，不是采集卡顿。
- M5-02 的 `{index}` 是「第一个可用空位」，不是持久递增计数器；删除 `_001` 后会复用，
  这是「不覆盖 + 找空位」的预期行为。

### 2.4 VBR 码率验收（轮 35 / M3-04#2 裁定）

VBR 不补 filler，静态画面天然用不满预算；「偏差 ≤20%」必须绑定内容类型，否则同一实现
在运动源与静态桌面上会得到相反结论。验收分三条，缺一不可：

| # | 内容 | 判据 | 实现 |
| --- | --- | --- | --- |
| ① | 指定运动源：全屏 `testsrc2`，20s，标称 6000kbps、峰值 9000kbps | 逐秒均值偏差 ≤20%（跳过首尾各 1s） | `g5_format.ps1` `m3-04-vbr-motion-nominal` |
| ② | 任意内容（运动源 + 静态桌面各录一段） | 单秒峰值 ≤ 配置峰值上限（102% 容差） | `m3-04-vbr-peak-any-content` |
| ③ | 静态桌面（无运动源，15s） | **只记录** avg/min/max，不作偏差判定；已知会显著低于标称 | `m3-04-vbr-static-recorded`（只断言录制完成与 mode=vbr） |

补充：VBR 与 CBR 互不覆盖（VBR 后再跑 CBR 仍逐秒恒定）仍由 `m3-04-mode-isolation` 覆盖；
`cbr_filler_bytes=0` 是 VBR 的定义性断言。禁止为了让静态桌面「贴标称」而给 VBR 加 filler——
那是 CBR 的定义。

## 4. 长时间录制稳定性

### 4.1 验收用例

| 编号 | 场景 | 步骤 | 通过判据 |
| --- | --- | --- | --- |
| LT-01 | 8 小时连续录制 | B 机 1080p30 全屏，全程不操作 | 文件完整可播；内存增长 ≤ 50MB；句柄数增长 ≤ 100；音画偏差 ≤ 100ms |
| LT-02 | 8 小时音频漂移 | 同时录制系统声与麦克风，第 1 分钟/4 小时/8 小时各做一次「拍手 + 秒表」 | 三个时间点偏差均 ≤ 100ms，且**不随时间单调增大** |
| LT-03 | 8 小时含静音段 | 中途静音 30 分钟再恢复 | 总时长准确；恢复后音画同步；无进度条跳跃 |

### 4.2 M6-09「完整可播 + 音画同步」的判据注释（轮 35 裁定 / 轮 36 落地）

> 只补判据口径，**不改 01 的需求原文**。

**(1)「完整可播」= 三件套**（原「ffmpeg 全解 stderr 为空」口径作废——它会把落盘端行为当成文件缺陷）：

| # | 判据 | 命令 |
| --- | --- | --- |
| ① | 解码零错误：退出码 0，stderr 无解码错误行 | `ffmpeg -v error -i F -f null -vsync 0 -`（ffmpeg 9 已移除 `-vsync`，等价 `-fps_mode passthrough`） |
| ② | 帧数与 DTS：视频帧数 = `frames_encoded`；每条流 DTS 严格递增（无重复、无倒序） | `ffmpeg -v error -i F -f framecrc -` |
| ③ | 默认 vsync 下的 `[null @ ...] non monotonically increasing dts to muxer` **不计** | —— |

> ③ 的依据：该警告是 null muxer 的 CFR 帧率转换产物（把平均 33.35ms 的帧流按 1/30 取整，边界处产生重复 DTS），
> 不是文件缺陷。轮 35 实测：同一窗口（16,000~16,667s）包级 DTS `dup=0 / backwards=0`，
> framecrc 逐帧 DTS 严格递增，exit=0 且无解码错误。

**(2)「音画同步」= 尾点偏差单独判定**（轮 36 R1）：

- 尾点偏差 = 文件末尾音轨末尾 PTS 与视频轨末尾 PTS 之差，判据 **≤ 100ms 且 ≤ 3 × 内部采样点最大偏差**；
- 只看「最差点 ≤100ms」不够：轮 35 尾点 99ms 只差 1ms 属余量运气（机制上界 186ms），重跑可能 120ms 直接 FAIL；
- 收尾实现要求：主循环结束后按视频轨末尾 PTS 补齐音频（真实音频优先，不足部分补静音，上限 200ms），
  **音轨不得短于视频**。

## 7. 验收判定规则

### 7.1 缺陷分级

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| **阻塞（Blocker）** | 录制无法完成或产物不可用 | 录制后文件打不开、进程崩溃、丢音轨 |
| **严重（Major）** | 功能可用但结果明显错误 | 音画不同步 > 500ms、选区错位、内存持续上涨 |
| **一般（Normal）** | 体验或边界问题 | 提示文案错误、极端场景回退、少量丢帧 |
| **轻微（Minor）** | 视觉或文字问题 | 对齐、字体、翻译 |

### 7.2 版本准入门槛

**V1.0 发布判据（全部满足才可发版）**：

1. 01 文档中 **66 条 V1.0 需求**验收全部通过，无一条降级为「已知问题」。
2. 阻塞级缺陷 **0**；严重级缺陷 ≤ 3 且均有明确计划。
3. LT-01、LT-02 各连续通过 **3 次**（非偶然通过）。
4. ER-01 / ER-04 两项故障注入各通过 **3 次**（ER-01 物理断电以 **ER-02 强杀代理**，证据里须标注「代理验证」）。
   **ER-08（TDR）属 V1.5（M8-09），不在 V1.0 判据内**——决策与理由见 `docs/13-ER08决策.md`。

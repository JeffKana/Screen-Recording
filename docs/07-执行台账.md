### 关于「同 SHA」的口径（避免误读）

- **包内 exe == build-release 产物**：本轮由脚本**内置比对**（对象是**从 zip 解压出来的文件**），
  实测两侧 SHA256 完全一致（`dist/release-summary.json` 的 `zip_sha_matches_build=true`）。
- **两次构建之间 SHA 相同**：**做不到，也不该这么要求**——MSVC 链接产物含时间戳/调试 GUID，
  同一份源码两次构建的 exe 哈希会变（实测：同一份源码先后两次打包，sr-ui 哈希从 `A0C7ECA1…` 变成 `29394B03…`）。
  「同源」由 `source_fingerprint`（src/ + CMakeLists + vcpkg.json 的 SHA256 汇总）证明。
- **开发构建 vs 发布构建**：`SR_TEST_HOOKS=OFF` / `SR_BUILD_TOOLS=OFF` 与开发构建**必然**哈希不同
  （这是 G6 方案的要求），脚本里如实记录 `dev_same_sha_as_release=false` 并附原因，不掩饰。

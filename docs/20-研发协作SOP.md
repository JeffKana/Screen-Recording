# 20 · 研发协作 SOP（任务 → PR → CI → 验收 → 合并 → 下发）

> 2026-11-11 制定 · 适用：本项目全部后续轮次（轮 45 起强制执行）
> 一句话：**主分支只接受合并；一切改动走分支 + PR + CI；验收结论只由验收方给。**

---

## 0. 角色与产出

| 角色 | 代号 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 规划/裁决 | **O0** | 切任务卡、裁定口径、**唯一合并权**、打 tag | 不写实现代码 |
| 执行方 | **S1~S6 / V1** | 按卡实现、跑用例、出四件套、开 PR | 不自评「已验收」、不改 `verify/` 尺子 |
| 验收方 | **E1** | 独立重跑、逐条判定、写台账、给结论 | 不改 `src/`、不改用例 |
| 机器 | **CI** | 构建 + 文档/契约/覆盖一致性 | 不替代本地集成验收 |

> 验收方与执行方必须是不同主体（同一模型可扮演，但**不得引用执行方结论**）。

---

## 1. 分支模型

| 项 | 规则 |
| --- | --- |
| 长期分支 | 只有 `main`（受保护：禁删除、禁强推） |
| 工作分支 | `round/<NN>`，从**最新 main** 拉，一轮一分支 |
| 卡片提交 | 一卡至少一次提交，message 前缀 `[<阶段>/<角色ID>-<序号>]` |
| 示例 | `[G5/S1-009] 窗口尺寸跟随：pool.Recreate + ComPtr 持有` |
| tag | 里程碑 `v0.x.y-baseline`；轮次可选 `round-<NN>` |
| 生命周期 | 合并后**立即删除**工作分支（远端 + 本地） |

一轮里若某卡需要独立回滚，才拆成两个分支，并在 PR 描述里写明原因（默认不拆）。

## 2. 闭环七步

| # | 环节 | 触发条件 | 责任方 | 产出 | 通过标准 | 异常处置 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **下发任务卡** | 上一轮已合并到 main | O0 | `tasks/<阶段>/<角色>-<序号>/TASK.md` + `docs/08` 更新 | 卡有需求锚点、文件域、判据、四件套要求 | 卡有歧义 → 在下发前修，不带着走 |
| 2 | **开工** | 卡已进 main | 执行方 | 分支 `round/<NN>` | `git switch -c round/45 origin/main` | 分支落后 → `git rebase origin/main` |
| 3 | **执行** | 分支就绪 | 执行方 | 代码 + 用例 + 四件套 | 本地判据全绿；双构建零告警；产物不入库 | 失败即停，写 HANDOFF 说明卡点 |
| 4 | **提交 PR** | 分支推送到远端 | 执行方 | PR（模板必填） | 标题/描述/自测/未做项齐备 | 描述缺项 → 验收方直接退回，不进验收 |
| 5 | **CI** | PR 创建或更新 | 机器 | 三个 job 的报告 | `checks` / `build (msvc)` / `build (mingw)` 全绿 | 红 → 执行方修复重推；**不计入验收轮次** |
| 6 | **验收** | CI 全绿 | 验收方 | 验收报告 + 台账行 | 逐条 PASS/PARTIAL/FAIL；结论不宽于证据 | 不通过 → PR 置 `changes requested`，写明缺什么 |
| 7 | **合并与下发** | 验收通过 | O0 | 合并提交 + tag + 下一轮卡 | `--no-ff` 合并；删除分支；台账/覆盖表已回写 | 冲突 → 执行方 rebase 后重跑受影响用例 |

> 关键顺序：**先合并，再发下一轮卡**。执行方永远从 main 拉分支，不从别人分支拉。

## 3. PR 规范

### 3.1 粒度

- 一轮一 PR；PR 内按卡顺序列改动。
- 单 PR 改动建议 ≤ 1500 行（不含用例生成物）；超出说明为什么不能拆。

### 3.2 必填内容（模板见 `.github/pull_request_template.md`）

| 字段 | 要求 |
| --- | --- |
| 本轮任务卡 | 列出卡号，链接 `tasks/.../TASK.md` |
| 需求 → 证据 | 每条子句一行：需求号 / 判据 / 命令 / 结果 |
| 自测结果 | 实际跑的用例名与 `N PASS / M FAIL`，**贴原始输出行** |
| 未做与挂账 | 明确写「未做」，并给下一步归属 |
| 风险与回退 | 影响面、回滚方式 |
| 自检清单 | 勾选：产物未入库 / 双构建零告警 / 未改 `verify/` |

### 3.3 禁止

- 在 PR 里写「已验收」「全部通过」这类结论性措辞（结论只能由验收方出）。
- 提交 `build-*/`、`verify/artifacts/`、`tasks/**/artifacts/`、`*.mkv`、`*.part`、`dist/`。
- 未在卡内申报的跨文件域改动。

## 4. CI 规范

### 4.1 作业

| job | 内容 | 大约耗时 |
| --- | --- | --- |
| `checks` | `contract_check` / `coverage_report --check` / `card_consistency_check` / `domain_table_check` | ~1 min |
| `build (msvc)` | VS2022 x64 Release 构建 + **告警即失败** | ~4 min |
| `build (mingw)` | MSYS2 MinGW64 Release 构建 + **告警即失败** | ~4 min |

### 4.2 边界（诚实声明）

CI **不做**集成验收：采集/编码/窗口/GUI 依赖真实桌面与 GPU，托管 runner 上结果不可信。
集成用例（`g4_*` `g5_*` `g3_*` `ui_smoke`）由**验收方在本机独立重跑**，CI 只保证「编译得过、文档不漂」。

### 4.3 失败处置

1. 看 job 日志定位；
2. 本地复现（`cmake --build` / 对应 python 工具）；
3. 修复后推同一分支，CI 自动重跑；
4. **CI 红期间不得请求验收**；连续 3 次同因失败 → 升级为缺陷单，评估是否卡本身有问题。

## 5. 验收规范

| 项 | 规则 |
| --- | --- |
| 验收对象 | **分支内容**（`git diff main...round/NN`），不是 PR 描述 |
| 前置 | CI 三 job 全绿、PR 模板无空缺 |
| 方法 | 本地切分支 → 独立重跑判据 → 对照 `docs/01` 原文 |
| 结论 | PASS / PARTIAL / FAIL / BLOCKED 四档；`BLOCKED` 不计入分母 |
| 留痕 | `docs/07` 一行（一行制）、`docs/09` 覆盖表、`.codebuddy/plans/验收报告-轮NN.md` |
| 不通过 | PR 置 `changes requested`；写明「缺哪条证据 / 哪条判据不符 / 需要什么」；**不改代码** |

---

## 6. 合并规范

| 项 | 规则 |
| --- | --- |
| 谁合 | **只有 O0**（或 O0 明确授权的人） |
| 怎么合 | `git merge --no-ff round/NN`，保留轮次拓扑；不 squash（轮次信息比线性历史更值钱） |
| 合并信息 | `round NN: <一句话>（S=xx.x）` |
| 合并后 | 打 tag（里程碑或轮次）→ 删分支 → 回写 `docs/08` → 下发下一轮卡 |
| 冲突 | 执行方 rebase 到最新 main 并重跑受影响用例，禁止用「以我的为准」硬解 |

## 7. 对应关系（可追溯）

```
任务卡 tasks/G5/S1-009/TASK.md
   └── 分支 round/45
         └── 提交 [G5/S1-009] ...
               └── PR #12  (base: main)
                     ├── CI: checks / build(msvc) / build(mingw)
                     ├── 验收报告 .codebuddy/plans/验收报告-轮45.md
                     ├── 台账 docs/07 一行（轮 45 / V1 / ... / S=xx.x）
                     └── 合并提交 "round 45: ..." + tag
```

追溯时三条命令够用：

```powershell
git log --oneline main --grep '\[G5/S1-009\]'   # 这一卡改了哪些提交
git log --oneline --merges                       # 每一轮一个合并点
git tag -n1                                      # 里程碑
```

## 8. 异常与回退

| 场景 | 处置 |
| --- | --- |
| CI 红 | 执行方修，重推；验收方不受理 |
| 验收不通过 | PR 退回，写清缺口；下一轮不占用新轮次，算**同轮返工** |
| 误提交大文件 | 未推送 → `git reset --soft` 重提；已推送 → `git rm --cached` + 历史改写需 O0 批准（强推保护会拦，需临时放开） |
| 合并后发现缺陷 | 开 `hotfix/<描述>` 分支单独 PR，**不直接改 main** |
| 长跑/锁文件 | `.lt01-running.json` 存在期间**禁止跑任何用例**（轮 34 D-60 教训） |
| 分支落后冲突 | rebase + 重跑受影响用例，不允许"合并时解决" |
| 验收方发现问题在自己侧 | 记为验收方 finding（如轮 34 的 D-60），不计执行方账 |

## 9. 检查清单

**执行方（开 PR 前）**

- [ ] 分支从最新 main 拉出，`git rebase origin/main` 无冲突
- [ ] 本地判据全绿，`N PASS / M FAIL` 原始输出已贴进 EVIDENCE
- [ ] 双构建零告警；`git status` 干净
- [ ] 无 `build-*/`、`*.mkv`、`*.part`、`artifacts/` 入库
- [ ] 四件套齐备，`## 交付状态` 与覆盖表口径一致
- [ ] PR 描述五项齐全，未写「已验收」

**验收方（合并前）**

- [ ] CI 三 job 绿
- [ ] 已切到分支独立重跑，未引用执行方结论
- [ ] 逐条判定，`BLOCKED` 已写明缺什么
- [ ] 台账一行 + 覆盖表已回写
- [ ] 报告里每个 finding 都有 remedy 与归属

**O0（合并时）**

- [ ] 验收结论为达标或明确的有条件达标
- [ ] 合并用 `--no-ff`，信息含轮次与 S 值
- [ ] tag 已打、分支已删、下一轮卡已进 main

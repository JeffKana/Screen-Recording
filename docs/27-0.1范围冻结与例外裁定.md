# 27 · 0.1 范围冻结与例外裁定

> 2026-11-20 · O0 裁定（用户拍板）
> **0.1（MVP）不做其他真机的兼容测试。** 本文把这句话落成可执行的范围与例外清单。

---

## 1. 裁定原文与解释

**「MVP 0.1 版本不做其他真机的兼容测试。」**

解释成三条：

1. **0.1 的验证范围 = 本机**（Win11 build 26200 / Intel UHD 770 / 单屏 100%）。不再为 0.1 等待或采购其它机型；
2. **不再有"真机 BLOCKED"这一档**——那 4 条与 `M1-27#1` 判为 **0.1 范围外（例外）**，既不标"已实现"，也不算"未通过"；
3. **GA（1.0）的门槛不变**：真机兼容与性能基线仍是 1.0 的前置，只是**不再压着 0.1**。

---

## 2. 两级发布模型（替代原来的「rc → GA」单线）

| 版本 | 定位 | 验证范围 | 对外措辞 |
| --- | --- | --- | --- |
| **0.1（MVP）** | 本地优先录屏工具的第一个可用版本 | **仅本机**：功能子句 111/116 + 单机 8h×2 + ER 重跑 | 「功能完整；**仅在 Win11 + Intel 核显单机验证**，其它机型未测」 |
| **1.0（GA）** | 通用可用版本 | 真机矩阵 + B 机性能基线 + LT 各 3 次 | 可写「多机型验证通过」 |

> 0.1 **不是** rc：rc 是"等待补齐验证"，0.1 是"范围已冻结、例外已列明"。两者都要求**不夸大**，区别在于是否还有未完成的验证计划压在同一条线上。

## 6. 明确不允许的三件事

1. **不许把例外写成"已验证"**——发布说明里出现"多机型兼容"即视为虚假陈述；
2. **不许用 0.1 的范围去改 `docs/01` 的版本标签**（需求仍是 V1.0，只是本次发布不覆盖全部验证）；
3. **不许把 0.1 当成 1.0 发**——`ga_ready=0` 继续保留在 `VERSION.txt`，直到真机补齐。

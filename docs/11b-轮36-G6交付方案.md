# 11 · 轮 36 G6 交付方案（安装包 / 发布构建 / 兼容性矩阵）

> 下发：2026-10-28 · 依据：验收方轮 36 指令 P1-4「G6 准备」
> 定位：**本轮只出方案，不出包**。G6 门（`docs/08` §3）的判据是
> 「MSVC Release 安装包可安装运行；无阻塞级缺陷」。

---

## 1. 范围与不做的事

| 做 | 不做（本轮） |
| --- | --- |
| 打包方案定稿（形态、目录、脚本、产物白名单） | 实际产出 zip / MSI |
| 发布构建开关与命令定稿 | 实际跑一遍发布构建并出包 |
| 兼容性矩阵表头定稿 | 填矩阵结果（要真机） |
| 安装 / 卸载 / 升级 / 残留的行为约定 | 实际安装验证 |
| 签名方案 | 买代码签名证书（外部依赖） |

**约束**（来自轮 36 指令 §5.3）：安装包**不得引入三方工具链**。
因此不引入 WiX / NSIS / InnoSetup 等外部打包器；只用系统自带能力（PowerShell + Compress-Archive）。

---

## 2. 打包形态选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A. zip + 安装脚本** | `ScreenRecorder-<ver>-win-x64.zip` 内含 `install.ps1` / `uninstall.ps1`，脚本用 `Copy-Item` + 注册表写卸载项 | 零三方依赖；可脚本化；改动成本最低 | 不写注册表卸载信息就没有「应用和功能」条目；无文件版本资源 | ✅ **V1.0 采用** |
| B. MSI（WiX） | 生成 .wixproj，用 WiX toolset 产出 MSI | 标准安装体验、卸载项、升级 | 引入三方工具链（违反指令）；WiX 需 .NET SDK | ❌ 不做 |
| C. EXE 安装器（自研） | 一个小 exe 做解压+写注册表 | 单文件分发 | 要自己实现解压/回滚/卸载，工作量≈B | ❌ 不做 |

**选 A 的理由**：G6 的判据是「可安装运行」，不是「安装体验」。
A 能在不引三方依赖的前提下满足判据，且**每一步都能在用例里重跑**（脚本化 = 可验收）。

## 3. 包内目录结构与产物白名单

```
ScreenRecorder-0.1.0-win-x64/
├── install.ps1              # 安装：建目录、拷文件、写卸载信息、创建开始菜单项
├── uninstall.ps1            # 卸载：删文件、删卸载项、保留用户成片
├── README.txt               # 安装步骤、最低系统版本、已知限制
├── bin/
│   ├── sr-ui.exe            # 主程序（产品）
│   └── sr-recorder.exe      # 录制子进程（产品）
├── runtime/                 # 运行时依赖（MSVC 运行库等；当前为 static CRT，待确认）
└── VERSION.txt              # 版本号 + 构建 SHA256 + 构建时间
```

**产物白名单（发布包只允许出现这两个 exe）**：

- ❌ `srctl.exe`（IPC 调试客户端）
- ❌ `srprobe.exe`（诊断探针）
- ❌ `*.pdb`、`*.ilk`、`*.obj`、`CMakeCache.txt`、`CMakeFiles/`

> `srctl` / `srprobe` 由 `SR_BUILD_TOOLS=OFF` 直接不编译，
> 而不是「编了再删」——删文件不能防止误打包，也留不住 debug 符号。

## 4. 发布构建开关

| 开关 | 默认 | 发布取值 | 作用 |
| --- | --- | --- | --- |
| `SR_TEST_HOOKS` | ON | **OFF** | 去掉产品二进制里的验收注入开关（`--preflight-fail` / `--fail-write-after` / `--inject-drop-every` / `--set-*` 等）。`SR_TEST_HOOKS=OFF` 时 `--help` 也不再列出这些参数。 |
| `SR_BUILD_TOOLS` | ON | **OFF** | 不编译 `srctl` / `srprobe`，从源头杜绝调试工具进包。 |
| 构建类型 | — | **Release** | G6 只认 MSVC Release。 |

**标准发布构建命令**（新增脚本 `verify/tools/build_release.ps1`，本轮未实现）：

```powershell
cmake -S . -B build-release -G "Visual Studio 17 2022" -A x64 `
      -DSR_TEST_HOOKS=OFF -DSR_BUILD_TOOLS=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --config Release
```

**发布包自检清单**（每条都要有可重跑的命令）：

| # | 检查 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 测试开关已消失 | `build-release\bin\Release\sr-recorder.exe --help` | 输出里**不含** `--inject-drop-every` / `--fail-write-after` / `--preflight-fail` |
| 2 | 调试工具不存在 | `Get-ChildItem build-release\bin\Release` | 只有 `sr-ui.exe` / `sr-recorder.exe`（+ pdb 不入包） |
| 3 | 无符号文件入包 | 解压后 `Get-ChildItem -Recurse -Filter *.pdb` | 0 个 |
| 4 | 版本可追溯 | `Get-Content VERSION.txt` | 含版本号 + 源 SHA256 + 构建时间 |
| 5 | 零告警构建 | 构建日志 | 0 warning（MSVC `/W4`） |

> **注意**：`SR_TEST_HOOKS=OFF` 会让**现有自动化用例**失去注入手段
> （`g5_inject` / `g5_fallback` / `g5_diag` 依赖 `--fail-*` / `--inject-drop-*`）。
> 因此验收流水线必须**分两个构建目录**：
> `build-msvc`（`SR_TEST_HOOKS=ON`，跑用例）与 `build-release`（`OFF`，只打包 + 冒烟）。
> 两者不可互相替换。

## 5. 安装 / 卸载 / 升级 / 残留（行为约定）

| 行为 | 约定 | 验证方式 |
| --- | --- | --- |
| 安装目录 | `%LOCALAPPDATA%\ScreenRecording\`（免管理员，逐用户安装） | 安装后目录存在 + 2 个 exe |
| 开始菜单 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\ScreenRecorder.lnk` | 快捷方式存在 |
| 卸载登记 | `HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\ScreenRecorder` → `UninstallString` 指向 `uninstall.ps1` | 注册表项存在 |
| 卸载范围 | 只删程序目录与注册表项；**不删**用户成片（默认输出目录 `%USERPROFILE%\Videos\ScreenRecording`） | 卸载后成片仍在 |
| 残留 | 卸载后 `%LOCALAPPDATA%\ScreenRecording` 整个目录删除；日志目录（若在程序目录内）一并删 | 目录不存在 |
| 升级 | 覆盖安装：先杀 `sr-ui` / `sr-recorder` 进程 → 覆盖文件 → 保留用户成片与设置 | 版本号更新、设置保留 |
| 最低系统 | Windows 10 1809（与 `docs/05` §3.1 一致） | 安装前置检查 |

## 6. 兼容性矩阵表头

矩阵的**维度**直接沿用 `docs/05` §3.1~§3.3，**结果列**统一为下列 6 列：

| 维度 | 组合 | 等级 | 必测项 | 结果 | 备注 |
| --- | --- | --- | --- | --- | --- |
| （§3.1 操作系统） | Win10 1809 / Win10 21H2 / Win11 23H2 / Win11 24H2 | 必测/抽测 | 安装→运行→录 60s→成片可播 | ☐PASS ☐PARTIAL ☐FAIL ☐N/A | |
| （§3.2 显示与图形） | DPI 100/125/150/200；混合 DPI；1/2/3 屏；热插拔；120/144/165Hz；720p~4K；HDR；混合显卡 | 同左 | 同左 | ☐PASS ☐PARTIAL ☐FAIL ☐N/A | |
| （§3.3 硬件与其他） | NVENC 代际 / QSV / AMF / ARM64 / 杀软 / 虚拟机 | 同左 | 同左 | ☐PASS ☐PARTIAL ☐FAIL ☐N/A | |

矩阵**行**按「维度 × 组合」展开，每行必须有：**录一段 60s 素材 → 抽帧比对 → 音画偏差**三件套，
不接受「跑起来没崩」当结论。

## 8. 风险

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| `SR_TEST_HOOKS=OFF` 后注入类用例无法在发布构建上跑 | 用例体系分裂 | 双构建目录（§4），用例只跑 `build-msvc` |
| 无代码签名证书 | SmartScreen 误报，用户首次运行被拦 | V1.0 用 zip + 明确说明；证书作为商业决策后置 |
| 免管理员安装 → 无法采 UAC 提权窗口 | M1-27 的场景在安装版里必然黑屏 | 与 M1-27 的「以管理员身份重启」入口一起交付 |
| 机器码绑定（证书）不可用 | 无法做机器码许可 | V1.0 不做许可校验 |

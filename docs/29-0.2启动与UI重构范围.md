# 29 · 0.2 启动与 UI 重构范围

> 2026-11-23 · O0 裁定
> **解冻（`docs/28` 第 3 条）：开启 0.2 线，主题是「UI 与交互重构」；0.1.x 线继续冻结。**

---

## 1. 决定

| 项 | 结论 |
| --- | --- |
| 技术路线 | **Win32 自绘 + 模块化**（不迁 Electron / WebView2） |
| 交互形态 | **工作台 + 悬浮条**：主窗口是录制工作台，录制中收进托盘与悬浮条 |
| 版本 | **0.2.0**（新线）；`0.1.0/0.1.1` 冻结，不再发补丁（除非阻塞级缺陷） |
| 参考产品 | Recordly（Electron/PixiJS，AGPL-3.0）——**只参考交互，不参考实现，不引入其代码** |
| 依赖 | **保持零三方依赖**；包体目标 ≤ 500 KB |

---

## 2. 为什么不上 Electron/WebView2

Recordly 的观感一半来自**编辑器**（时间轴、画布、属性面板）——那是我们 V1.5 的范围，0.2 不做。为"工作台 + 悬浮条"这层界面引入 Chromium/Edge Runtime，等于用 +150 MB 包体和 1~2 秒启动，换一点圆角阴影，与"解压即用、零依赖"的既有取舍冲突。

到 V1.5 真做时间轴时，再单独评估 WebView2 编辑层。

---

## 3. 重构后长什么样

```
┌──────────────────────────────────────────────────────────┐
│ ScreenRecorder            ● 就绪        [最小化到托盘]    │ 48px Header
├──────────────────────────────────────────────────────────┤
│ 源:[全屏▾] 区域:[…] 帧率:[30▾] 码率:[6000] 质量:[高清▾]   │ 控制条
│                                    [   ● 开始录制   ]     │
├───────────────────────────────────┬──────────────────────┤
│ 最近录制                           │ 设置（可折叠 320px）  │
│ ┌───────────────────────────────┐ │ 保存位置  [选择…]     │
│ │ 2026-11-23_141233.mkv         │ │ 命名模板  {date}_{time}│
│ │ 00:12:35 · 1.2 GB · 今天       │ │ 全局热键  F9/F10/F11  │
│ └───────────────────────────────┘ │ 日志级别  [info▾]     │
│ …                                  │ 编码器    软编（硬编不可用）│
├───────────────────────────────────┴──────────────────────┤
│ 采集 30.0 / 编码 30.0 fps · 丢帧 0 │ 剩余 62,215s │ 0.2.0  │ 状态栏
└──────────────────────────────────────────────────────────┘
```

**交互规则**

1. 设置**即时生效**，取消"确定/取消"对话框；非法值就地红框 + 不写盘；
2. 录制中控制条锁定，只留暂停/停止；窗口可缩到托盘，悬浮条接管；
3. 成片列表支持点击选中、双击播放、右键（打开目录/重命名/删除）；
4. 托盘图标随状态变化（就绪/录制/暂停/错误），菜单由快照驱动；
5. 键盘可达：Tab 顺序、Enter 触发主按钮、Esc 关闭面板。

## 4. 视觉规范（写进代码 token，别散落）

| 类别 | 值 |
| --- | --- |
| 底色 | `#0F1115`；卡片 `#161A20`；浮层 `#1D232B`；描边 `#2A313B` |
| 文本 | 主 `#E6EAF0`；次 `#98A2B3`；禁用 `#5A6472` |
| 强调 | `#3B82F6`；危险 `#EF4444`；成功 `#22C55E`；警告 `#F59E0B` |
| 圆角 | 卡片 8px；按钮/输入 6px；状态药丸 999px |
| 间距 | 4 / 8 / 12 / 16 / 24 五档，禁止魔法数字 |
| 字体 | Segoe UI Variable Text（回退 Segoe UI）；12 / 13 / 15 / 20 四档 |
| 动效 | 120~180ms ease-out；仅 hover / press / 面板展开；不做闪烁 |
| 窗口 | 默认 980×680，最小 860×560；`WS_EX_APPWINDOW`，非无边框拖拽 |

**DPI**：沿用 per-monitor v2 + `GetDpiForWindow`；布局按 96dpi 设计值 × scale 换算，禁止硬编码像素。

## 5. 代码结构（0.2 目标形态）

```
src/app/
  main.cpp              # 仅 WinMain + 装配（目标 <300 行）
  ui/
    theme.{h,cpp}       # 颜色/字号/间距 token、明暗切换、DPI 缩放
    draw.{h,cpp}        # 圆角矩形、阴影、文本、图标（GDI+/D2D 二选一）
    layout.{h,cpp}      # 纵向栈 + 网格 + 最小宽高约束
    controls.{h,cpp}    # Button/Toggle/Card/StatusPill/ListRow/Field
    main_window.{h,cpp} # 工作台
    settings_panel.{h,cpp}
    toolbar.{h,cpp}     # 悬浮条
    tray.{h,cpp}        # 托盘 + 菜单
  AppConfig.*           # 保留
  RecorderController.*  # 保留（只经 IPC）
```

**硬约束**：`ui/` 不得直接持有采集/编码对象；所有动作走 `RecorderController`。

---

## 6. 非目标（0.2 明确不做）

- 时间轴/裁剪/注释等编辑能力（V1.5）；
- 新的采集/编码/封装能力（内核冻结）；
- MP4 崩溃恢复、真机兼容矩阵（`docs/27` 例外项照旧）；
- 引入任何三方 UI 库、图标库、字体文件。

## 7. 验收门槛

| # | 判据 |
| --- | --- |
| 1 | **行为等价**：`ui_smoke` 原 103 条全绿（可增不可减），其余 `g3_*/g4_*/g5_*` 零回归 |
| 2 | **可测**：新增 `ui_theme.ps1`（token/DPI/颜色采样 ≥10 条）、`ui_workbench.ps1`（列表/设置即时保存/状态栏 ≥20 条） |
| 3 | **性能**：spawn→窗口可见 ≤300ms；包体 ≤500 KB；启动内存 ≤80 MB |
| 4 | **视觉**：关键区域颜色采样与 token 一致（容差 ≤4/255）；不许出现系统灰底控件 |
| 5 | **代码**：`main.cpp` <300 行；`ui/` 单文件 ≤600 行；零新增依赖 |
| 6 | 三构建零告警；CI 三绿；契约 8/8 |

DPI 150% 仍需真机（与 M6-06 同源），本机按 100% 验，150% 标 BLOCKED 不得标 PASS。

# 决策单：ER-08（TDR）是否纳入 V1.0 验证

> 轮次：40｜下发：验收报告-轮39（轮 40 指令 P1 项）｜状态：**已决（不做，附替代）**
> 关联：M8-09 / V1.5｜`docs/05` §6 ER-08、§7.2 第 4 条｜`CONTRACT.md` G5-I7

## 1. 结论（一句话）

**ER-08 不纳入 V1.0 验证范围。** V1.0 不做 TDR（GPU 驱动超时复位）故障注入；
V1.0 的等价保障由 **ER-02（强杀）代理**承担，并在 V1.5 之前单开「TDR 注入卡」把 ER-08 补齐。
V1.0 的发布判据因此**不再**包含 ER-08。

## 2. 理由

| # | 理由 | 证据 |
| --- | --- | --- |
| 1 | ER-08 锚定的需求 **M8-09 是 V1.5 需求** | `docs/01-功能需求清单.md` M8-09 版本列 = V1.5 |
| 2 | 轮 22 已裁定「ER-08 属 V1.5，本轮不覆盖」，但**没有回写** `docs/05` §7.2 → 留下「发布判据要求 ER-08 / 覆盖表说未覆盖」的**遗留矛盾** | `docs/08-阶段重排与任务清单.md:359-360`；`docs/05` §7.2 第 4 条仍写「ER-01 / ER-04 / ER-08 各通过 3 次」 |
| 3 | TDR 无法在本机稳定自动化：需要真实 GPU 驱动超时复位，不是「跑一次没崩」能代替的 | `CONTRACT.md:252` G5-I7「属 V1.5，不得以『未崩溃』代替」；`verify/cases/g5_inject.ps1:3-4` 同一口径 |
| 4 | 即便做，V1.0 也没有对应需求条目可挂 | `docs/01` M8-09 = V1.5 |

## 3. 「做 / 不做 / 替代」

- **做**：本轮不做。触发条件＝V1.5 开工时单开任务卡，需要一张能稳定触发 TDR 的机型 + 注入手段。
- **不做**：V1.0 明确**不**把 ER-08 列为发布判据项，也**不**在覆盖表里记为「已通过」。
- **替代**：V1.0 用 ER-02（进程强杀）覆盖「异常退出后不丢数据、进程不崩」这段风险：

  | 替代项 | 覆盖的风险 | 落点 |
  | --- | --- | --- |
  | ER-02（进程强杀） | 录制进程被强杀后 `.part` 可修复、产物可播 | `verify/cases/g5_fallback.ps1`（兜底提交 + `--repair` + 可播断言）、`verify/cases/g5_lt01.ps1`（续跑） |
  | ER-01（物理断电） | 非正常掉电留下的分片可恢复 | 以 ER-02 强杀作为**代理**，证据里必须标注「代理验证，非物理断电」 |

  边界：**代理验证 ≠ 物理断电**，不得写成「断电恢复已验证」。

## 5. 对 V1.0 发布结论的影响

- ER-08 **不再**是 V1.0 不可发布的原因之一。
- V1.0 仍不可发布：剩余无卡子句（轮 40 收口后仍有 21 条）、M1-27#1 的黑屏一侧环境不可复现、
  M6-06（150% DPI）环境 BLOCKED，以及 §7.2 其它判据（兼容性矩阵、性能基线）未跑完。

## 2. 裁定：M3-04#1 判据改为「平均 + 峰值」

`docs/01` M3-04 的验收要点，**第 1 句**原文：

> CBR 模式下成片码率波动 ≤ 10%

**替换为**：

> CBR 模式下**全片平均码率**与标称偏差 ≤10%，且**任意单秒**码率不超过标称的 2 倍。
> （逐秒方差与滑窗方差受编码器实现限制，**不作判据**；单秒 2× 为硬挡板，不可放宽。）

## 3. 为什么选 A（而不是 B/C）

- **B（换硬编）**：只在有硬编的机器成立，本项目矩阵要覆盖三种 GPU 才敢默认；本机只有 Intel UHD 770，无法自证。
- **C（秒预算节流）**：靠喂复制帧把字节压回去，代价是**画面冻结**（极端内容下最多 1 秒）。屏幕录制里"画面卡住"比"文件略大"更伤用户。
- **A**：CBR 在行业里的定义就是"长时平均 + 峰值上限"，逐秒方差是**产物指标**而非**需求指标**；0.4% 的全片偏差已经证明码控有效。这是把标准落在真实约束上，不是迁就实现。

## 4. 硬约束（落地时不得越界）

1. **单秒 2× 挡板必须保留**，且对全部有效桶逐个判——它挡的是 IDR/P 帧突发失控（历史出现过 16,699kbps、22,757kbps）。
2. 平均判据的统计口径写死：**全片 `bytes_written / duration`** 与 `标称 kbps × 1000 / 8` 相比，**不允许**用"逐秒再平均"代替（两者在突发内容下会差出两位数）。
3. 本轮**只改判据与用例**，不再动 `src/encode/`；V1.5 的码控改进（IDR/P 帧预算）继续挂 `docs/17 §7`。
4. 反向护栏必须有两条：平均超 10% → FAIL；单秒超 2× → FAIL。**缺一不可**，否则新判据退化成空测。
